# Agent center language

The agent center organizes the owner's project work and presents recorded Claude Code activity. Its terms describe work and evidence, independently of the BiBilen marketplace domain.

## Projects and work

**Project**: A logical body of work with its own instructions, participants, access choices and history. A project persists when its folder moves.
_Avoid_: Folder, office, session as synonyms for project.

**Workspace**: A specific checkout in which project work takes place. One project may have multiple workspaces, such as separate branches being worked on simultaneously.
_Avoid_: Treating every checkout as a different product.

**Office**: A visual representation of a project's team and recorded activity. A character's presence does not establish that work is running.

**Agent profile**: A reusable role definition describing expertise and expected behavior. It is not a running worker or a shared conversation.
_Avoid_: Using agent to mean both a template and a live participant without qualification.

**Participant**: A particular lead or specialist taking part in a particular session. Two participants using the same agent profile have separate identities.

**Task**: An assigned piece of work with a fixed project and workspace scope. A reported result and verified completion are separate claims.

**Session**: A particular Claude Code conversation belonging to recorded project work. Changing the selected project in the panel does not move the conversation.

**Handoff**: A recorded assignment or transfer between participants. Cross-project handoffs are explicit new assignments with selected source material.

**Gökhan**: The coordinator persona presented to the owner. Its conversations and project knowledge belong to the relevant project work; the persona is not a single shared memory across projects.

## Evidence and access

**Connection**: An explicitly assigned service/account/channel access relationship. Sharing a provider account does not automatically assign its access to every project.

**Live signal**: Current verified evidence that a particular participant is working or waiting. Connected, idle, last recorded and unknown are distinct states.

**Execution host**: A registered computer on which a workspace's Claude Code work runs. Its availability is distinct from a task's success or failure.

**Account limit**: The provider's reported shared allowance for an account. A per-project allowance is an owner's scheduling policy, not a new provider quota.
